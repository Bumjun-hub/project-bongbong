# 봉봉 애니메이션 생성 및 검수

## 현재: 192px 전용 자산

- 기존 생성 원본 행에서 sprite-gen `kcentroid` 방식으로 재추출했다. 화면에서 256px 이미지를 75%로 줄이는 대신 192px 셀을 1:1 CSS 픽셀로 표시한다. 수작업 도트 수정이나 새 모션 생성은 아니다.
- 대기 4장, 걷기 8장, 인사 5장의 순서와 속도를 유지했다. 걷기의 기존 자세 문제는 이 보정으로 해결되지 않는다.
- 수면은 기존 머리 크기 비율을 유지하도록 138px 셀로 별도 재추출했다. CSS `scale(0.72)`를 제거해 추가 축소를 피한다. 192px 영역의 하단 가운데에 정수 좌표로 표시한다.
- 런타임은 `bongbong-atlas-192.png`와 `bongbong-sleep-138.png`, 각각의 전용 manifest를 사용한다. 기존 자산과 사용자 원본은 보존했다.
- 재현 설정: `request-192.json`, `request-sleep-138.json`. 원본 행은 이전 생성 작업 폴더에 보존되어 있다.
- 추출 보고서 오류/경고 없음, 프레임 정적 시각 검사 및 TypeScript/Vite 빌드 통과. Computer-use 및 실제 창 시각 검사는 수행하지 않았다.
- Windows 화면 배율에 따른 물리 픽셀 변환과 작은 글자 등 원본 디테일 손실까지 완전히 없애지는 못한다.

## 표시 크기 및 이동 개선 (2026-09-16)

- 표시 영역 128 → 256px, 창 180×220 → 288×320으로 확대했다. 서 있는 프레임은 256px 셀을 CSS에서 축소하지 않는다.
- 창 이동 간격/거리를 32ms·2px → 16ms·1px로 변경했다. IPC 처리 시간이 추가되므로 실제 이동 주기는 환경에 따라 달라진다.
- 걷기 12프레임을 내장 image_gen으로 두 차례 생성했지만 다리 교차가 반복되는 문제가 남아 런타임에는 적용하지 않았다. 기존 8프레임을 유지하며 보행 자세 개선은 미완료다.
- 두 번째 탈락 후보와 실제 프롬프트를 candidates/walk-12-rejected.png 및 candidates/walk-12-prompt.txt에 보관했다.
- 이번 수정에는 Computer-use를 사용하지 않았다. 아래 실제 실행 확인 기록은 이전 버전의 결과다.

- 원본: public/character/bongbong.png (수정하지 않음)
- 제작: GPT 내장 image_gen으로 상태별 이미지 생성, sprite-gen 2.2.0으로 프레임 추출·투명 처리·아틀라스 합성·GIF 출력.
- sprite-gen 자동 생성 어댑터는 로컬 Codex CLI 버전 문제로 실패하여 이미지 생성 부분만 대화의 내장 도구로 실행했다. 별도 유료 API로 전환하지 않았다.
- 중간 생성물은 .sprite-work.local 및 Codex 시각화 작업 폴더에 보존. 앱은 공개 폴더의 최종 아틀라스와 상대 좌표 manifest만 사용한다.
- 모든 상태의 추출 및 아틀라스 보고서: ok=true, errors=[]

| 동작 | 프레임 | 속도 | 반복 | 검수 |
| --- | --- | --- | --- | --- |
| idle | 4 | 4fps | 반복 | 눈 열림→반쯤 감김→감김→열림 확인 |
| walk | 8 | 8fps | 반복 | 두 번째 생성 후보. 측면 보행과 팔 방향 교차 개선. 실험적: 보폭/관절 연결의 완전한 연속성은 보장하지 않음 |
| sleep | 4 | 2fps | 반복 | 앉은 자세, 감은 눈, 작은 호흡 변화 확인 |
| wave | 5 | 6fps | 1회 | 손 올림→흔듦→내림, 앱에서 종료 후 Idle 확인 |

걷기 첫 후보는 같은 다리 동작 반복 문제로 제외했다. 재생 속도나 프레임 순서 조작으로 문제를 숨기지 않았다.
생성 프레임에는 세부 얼굴/옷 무늬의 미세한 차이가 있으며 원본과 픽셀 단위로 일치하지 않는다.
수면은 화면에서 머리 크기가 과도하게 커지지 않도록 표시 배율 0.72를 적용한다.
원본의 정면에 가까운 대기와 측면 걷기 사이에는 자세 변화가 있다.

## 실제 실행 확인

- TypeScript 및 Vite production 빌드 통과.
- Tauri 개발 실행 컴파일 통과.
- 투명 창에서 네 상태가 표시됨.
- Sleep 클릭 → Wave 확인.
- Wave 단축키 후 약 1초에 Idle 확인(한 번만 재생).
- Walk 프레임과 실제 창의 이동 확인.
- Sleep에서 드래그: 창 좌표 (1473,203) → (1405,127), 종료 직후 Idle 확인. 인사 중복 없음.
- 모든 Windows 배율/모니터 조합 및 설치 파일 배포 테스트는 수행하지 않음.

## 걷기 최종 프롬프트 핵심

원본 캐릭터의 머리·안경·붉은 셔츠·목걸이·청바지·운동화·도트 표현을 유지.
오른쪽 측면의 8프레임 두 걸음 보행: 가까운 다리 앞 접지 → 하강 → 먼 다리 통과 → 먼 다리 전진 → 먼 다리 앞 접지 → 하강 → 가까운 다리 통과 → 가까운 다리 전진.
팔은 반대 다리와 함께 교차하고, 크기/바닥선 고정, 투명 배경, 잘림/그림자/문자 금지.
다른 상태의 전체 프롬프트는 같은 폴더의 idle.txt, sleep.txt, wave.txt에 보존했다.
walk.txt는 첫 시도 프롬프트이며 최종 재생성 때 위 측면/교차 조건을 강화했다.
